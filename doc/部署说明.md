# SiYuan-AI-Expand 部署说明

本文档面向将 SiYuan-AI-Expand 部署为 Windows 服务的运维人员，覆盖发布、安装、卸载、首次配置、权限、配置变更语义、安全注意事项与故障排查。

---

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11、Windows Server 2016 及以上（x64） |
| .NET 运行时 | **无需安装**。发布为 `win-x64` 单文件自包含包，包含 .NET 运行时与原生依赖。 |
| 思源笔记 | 一套可访问的思源笔记实例（本机或局域网内），并具备管理员 API Token。 |
| 网络 | 同步主机需能访问思源实例的 HTTP 端口（默认 `127.0.0.1:6806`，可配置）。 |
| 权限 | 安装/卸载脚本自动申请管理员提权（UAC）；服务/计划任务注册、ACL 与 `sc.exe` 操作均要求管理员。 |
| 最低思源版本 | **待实测填写**（需支持 `prependBlock`、`renameDocByID` 内核 API；详见第 9 节）。 |

## 2. 发布

在工作目录（脚本所在根目录）以 PowerShell 执行：

```powershell
.\publish.ps1
```

`publish.ps1` 实际执行：

```powershell
dotnet publish src/SiYuanSync.App -c Release -r win-x64 --self-contained `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true -o publish
```

产物：`publish\SiYuan-AI-Expand.exe`（单文件自包含 exe，内嵌 .NET 运行时、原生库、Web 静态资源）。

发布耗时约 1–2 分钟（自包含 + 单文件压缩）。`publish\` 目录已纳入 `.gitignore`，发布产物不进版本库。

## 3. 安装（Windows 服务 / 计划任务）

直接运行即可，脚本会自动申请管理员提权（UAC）：

```powershell
.\install.ps1
```

`install.ps1` 依次完成：

1. **安装目录**：提示确认安装目录，回车沿用上次/默认。默认 `E:\Software\FreeInstall\SiyuanExpand`；重装时自动从 `%ProgramData%\SiYuan-AI-Expand\install-record.json` 或已注册服务 binPath 读取上次目录。把 `publish\` 下产物复制到该目录。
2. **Web 端口**：提示确认端口，回车沿用上次/默认。默认 `61122`；从 `config.json` 或安装记录读取上次值。把端口写入 `config.json` 的 `web.port`（端口在 Kestrel 启动时绑定，**必须在服务启动前写入**，否则程序用内置默认 6807）。
3. **数据目录与 ACL**：创建 `%ProgramData%\SiYuan-AI-Expand\`，禁用继承，仅保留 `BUILTIN\Administrators` 与 `NT AUTHORITY\SYSTEM` 完全控制（容器与对象继承）。
4. **清理旧实例**：若已存在同名服务或计划任务，先停止并删除，便于重装。
5. **注册运行**：
   - **NSSM 优先**（`nssm.exe` 在 PATH 中）：`nssm install` 注册服务，设 `AppDirectory`、`AppExit Default Restart`、`AppRestartDelay 5000`，并叠加 `sc.exe failure reset= 86400 actions= restart/5000/restart/10000/restart/30000`（双层失败恢复），`start= auto`，最后 `sc.exe start`。
   - **计划任务兜底**（本机无 NSSM 且用户确认采用）：注册名为 `SiYuan-AI-Expand` 的计划任务，SYSTEM 身份、`AtStartup` 触发、`--console` 模式运行、`ExecutionTimeLimit 0`、`RestartCount 999 / RestartInterval 1min`。
6. **写安装记录**：把安装目录、端口、运行方式写入 `install-record.json`，供下次重装自动沿用。

服务名 / 任务名均为 `SiYuan-AI-Expand`。服务模式默认以 `LocalSystem` 运行；计划任务以 `NT AUTHORITY\SYSTEM` 运行——两者均满足 `%ProgramData%\SiYuan-AI-Expand\` 写权限。

> 计划任务模式说明：进程作为普通后台进程运行（非 SCM 服务），因此用 `--console` 跳过程序的 `UseWindowsService` 分支。Console 日志输出在无桌面会话下被丢弃，文件日志（`logs\app-*.log`）与 Windows 事件日志照常生效。开机自启；进程异常退出约 1 分钟后由任务计划程序重启。

## 4. 卸载

直接运行（自动 admin 提权）：

```powershell
.\uninstall.ps1
```

`uninstall.ps1` 同时尝试清理两种运行方式（兼容历史装法与切换）：

1. **计划任务**：`Stop-ScheduledTask` + `Unregister-ScheduledTask SiYuan-AI-Expand`（不存在则跳过）。
2. **服务**：`sc.exe stop` → 等 2 秒 → `sc.exe delete`；若本机有 `nssm.exe` 再 `nssm remove SiYuan-AI-Expand confirm` 兜底；轮询等待 SCM 完成删除。

数据目录 `%ProgramData%\SiYuan-AI-Expand\`（含 `config.json`、`state.db`、`logs\`、`install-record.json`）与安装目录（exe）**均默认保留**，便于回滚或问题排查。如需彻底清理，请手动删除。

## 5. 首次配置

服务首次启动时，`%ProgramData%\SiYuan-AI-Expand\config.json` 不存在或字段为空（默认值），系统进入待配置状态。两种配置方式：

### 方式 A：Web 配置页（推荐）

1. 服务/计划任务已启动后，浏览器访问 `http://127.0.0.1:61122/`。
2. 首次未设置 Web 密码时可直接进入；登录后立刻设置密码（密码变更会使所有已签发 session 失效）。
3. 在 **思源连接** 区域填写 `serverUrl`（如 `http://127.0.0.1:6806`）与 `token`（思源管理员 API Token），点击"测试连接"验证。
4. 在 **默认笔记本** 区域选择一个 notebook。
5. 在 **项目** 区域新增同步项目：填写本地目录、思源目标 notebook、目标父文档路径（hpath）等。
6. 点击 **立即同步**，系统会自动在思源中按 hpath 逐级创建父文档，并将本地 `.md` 文件同步为思源文档。

### 方式 B：控制台调试模式

在安装目录（或 `publish\` 开发产物目录）以普通用户运行：

```powershell
.\SiYuan-AI-Expand.exe --console
```

控制台模式与 Windows 服务模式共用同一数据目录（`%ProgramData%\SiYuan-AI-Expand\`）。

> 注意：服务模式下 `LocalSystem` 默认具备数据目录写权限；若以普通用户运行 `--console`，该用户必须对 `%ProgramData%\SiYuan-AI-Expand\` 具备写权限（非管理员用户默认不可写 `C:\ProgramData\` 下的子目录）。建议控制台调试时由管理员账号运行，或临时调整目录 ACL。

## 6. 数据目录与权限

| 路径 | 用途 |
|---|---|
| `%ProgramData%\SiYuan-AI-Expand\config.json` | 主配置（思源连接、Web 凭据、项目列表） |
| `%ProgramData%\SiYuan-AI-Expand\state.db` | SQLite 状态库（文件 hash、sync_run 历史） |
| `%ProgramData%\SiYuan-AI-Expand\logs\app-*.log` | 按日 + 10MB rolling 日志，保留 15 份 |

**服务账户写权限**：服务进程必须对上述目录具备写权限。
- 默认 `LocalSystem`：自动满足。
- 改用域/本地账户（服务模式）：`sc.exe config SiYuan-AI-Expand obj= <account> password= <pwd>` 后，手动为 `%ProgramData%\SiYuan-AI-Expand\` 授予该账户写权限（`install.ps1` 的 ACL 只放行 `Administrators` + `SYSTEM`）。计划任务模式在 `Register-ScheduledTask -Principal` 指定账户，同样需保证该账户对数据目录有写权限。

## 7. 配置变更生效语义

| 变更方式 | 生效时机 |
|---|---|
| 通过 Web 配置页修改（推荐） | **即时生效**（连接/笔记本/项目/token/密码等业务字段） |
| 直接编辑 `config.json` | 需 **重启服务** 才会重新加载 |
| `web.bind` / `web.port` | **必须重启服务**（Kestrel 监听在启动时绑定） |

Web 配置页修改时，`ConfigStore` 在内存权威副本更新成功后才返回，业务读取始终走内存快照；同时原子写回 `config.json`，确保进程重启后状态一致。

## 8. 非 loopback 绑定的安全风险

默认 `web.bind = 127.0.0.1`，仅本机访问 Web 配置页。

若将 `web.bind` 改为 `0.0.0.0` 以便局域网访问，请务必注意：

- **Web 传输为纯 HTTP，无 TLS**：所有请求体（包含思源 token、Web 密码、session cookie）将以明文形式在网络上传输，存在凭据泄露风险。
- **session cookie 默认未标记 Secure**：在非 HTTPS 下，浏览器仍会发送 cookie，但中间人可截获。
- **建议**：
  - 仅在 **受信任的隔离局域网** 内开放非 loopback 绑定；
  - 生产环境应通过 **反向代理**（如 IIS、Nginx、Caddy）提供 TLS 终结，前端反向代理到 `127.0.0.1:61122`；
  - 反向代理场景下，仍保持 `web.bind = 127.0.0.1`。

合法的 `web.bind` 取值：`127.0.0.1`、`localhost`、`0.0.0.0`、`::1`（其余值会被校验拒绝）。

## 9. 最低思源版本（待实测填写）

本工具依赖以下思源内核 API：

- `listNotebooks`
- `createDocWithMd`
- `getDocIDsByHPath`（或等价按 hpath 查询）
- `renameDocByID`
- `removeDocByID`
- `getChildBlocks`
- `deleteBlock`
- `prependBlock`（更新文档首行标题时使用）
- `appendBlock`（fallback）

> **待实测后填写**：以上 API 中，`prependBlock` 与 `renameDocByID` 在不同思源版本间行为可能不同。请在目标思源实例上完成首次端到端同步测试后再确认最低支持版本。建议从当前主流稳定版（v3.x）开始测试。

## 10. 故障排查

| 现象 | 排查步骤 |
|---|---|
| 服务启动失败 | 1. **事件查看器** → Windows 日志 → 应用程序 → 来源 `SiYuan-AI-Expand`（Error 级别，事件 ID 1/2 表示配置损坏/启动异常）<br>2. 查 `%ProgramData%\SiYuan-AI-Expand\logs\app-*.log` |
| Web 配置页无法访问 | 1. 确认运行状态：服务模式 `sc.exe query SiYuan-AI-Expand`，计划任务模式 `Get-ScheduledTask SiYuan-AI-Expand`<br>2. `netstat -ano \| findstr 61122` 确认端口监听<br>3. 防火墙：默认 `127.0.0.1` 无需额外放行；改 `0.0.0.0` 需放行 61122 端口 |
| 同步失败（思源不可达） | 1. Web 配置页 → "测试连接"<br>2. 确认思源实例运行且 token 有效<br>3. logs 查 `Retry` / `Transient` 标记 |
| 同步失败（认证） | 思源 token 过期或权限不足；Web 配置页重新填写后立即同步 |
| 控制台调试 | 在安装目录（或 `publish\`）运行 `SiYuan-AI-Expand.exe --console`，实时输出 INFO 日志，便于观察同步过程 |
| 配置损坏无法启动 | Program.cs 捕获 `ConfigCorruptException`（事件 ID 1）后非零退出。备份 `%ProgramData%\SiYuan-AI-Expand\config.json`，删除后让程序重新初始化为默认值，再通过 Web 重新配置 |

### 日志体系速览

- **文件**：`%ProgramData%\SiYuan-AI-Expand\logs\app-YYYYMMDD.log`，INFO 级别，按日 + 10MB rolling，保留 15 份。
- **控制台**：仅 `--console` 模式输出。
- **Windows EventLog**：仅 Error 级别写入，来源 `SiYuan-AI-Expand`。
- **敏感信息**：Serilog 已配置 `Destructure.ByTransforming<SiyuanConfig>`，日志中思源配置仅暴露 `serverUrl` 与 `hasToken: true/false`，**绝不写明文 token**。

## 11. 端到端首次部署速查

```powershell
# 1. 发布（普通用户即可）
.\publish.ps1

# 2. 安装（自动 admin 提权；NSSM 优先，否则计划任务；默认安装目录与端口回车沿用）
.\install.ps1

# 3. 浏览器访问 http://127.0.0.1:61122/，完成首次配置（思源 token / 默认笔记本 / 项目）

# 4. （可选）控制台调试模式：先停掉服务/计划任务，再在安装目录运行：
.\SiYuan-AI-Expand.exe --console

# 5. 卸载（自动 admin 提权）
.\uninstall.ps1
```
